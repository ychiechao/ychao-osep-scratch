Arduino 是什麼？
概念理解
▼

Arduino 就像一台「沒有螢幕、沒有鍵盤的小電腦」。它可以讀取外部的感測訊號（輸入），也可以控制燈光、馬達、蜂鳴器等裝置（輸出）。

🖥️
一般電腦執行軟體，Arduino 執行控制邏輯。兩者最大差別是 Arduino 可以直接和物理世界的元件連接。

訊號的兩種類型

類型值域用途例子
數位 Digital0 或 1（0V 或 5V）開關狀態LED亮滅、按鍵偵測
類比 Analog0～1023連續數值光線強度、溫度、旋鈕
✅ 我了解 Arduino 是一種微控制器開發板
✅ 我知道數位訊號只有 0 和 1，類比訊號是 0～1023

Scratch 如何控制 Arduino？
原理說明
▼

原版 Scratch 只能做電腦上的動畫，要控制 Arduino 需要一個「中介軟體」橋接兩者：

通訊流程
Scratch 積木程式 ↓ （積木指令） OSEP 轉譯程式（韌體） ↓ （USB / Web Serial） Arduino UNO ↓ （電子訊號） LED / 感測器 / 馬達
✅
OSEP 只需燒錄韌體一次，之後每次開啟瀏覽器直接連線即可，不需重複設定。
✅ 我了解 OSEP 是連接 Scratch 和 Arduino 的橋梁

什麼是 PWM？
概念說明
▼

PWM（脈寬調變）是一種用「快速開關」模擬類比電壓的技術。

PWM 比喻
亮度 255 → 一直亮（全速） █████████ 亮度 127 → 一半時間亮 █░█░█░█░█ 亮度 64 → 四分之一時間亮 █░░░█░░░█ 亮度 0 → 全暗 ░░░░░░░░░ 人眼感覺到的是「平均」亮度，PWM 值 0~255
💡
PWM 只能用在有 ~ 符號的腳位：D3、D5、D6、D9、D10、D11。這個實作請把 LED 模組改插到 D9。
LED 模組從 D13 拔出，插入 D9
S → D9 的 S 孔 ／ P → D9 的 V 孔 ／ G → D9 的 G 孔
D9 有 ~ 符號，支援 PWM 類比輸出（0-255）
✅ LED 模組從 D13 拔出，重新插入擴充板 D9 的 S/V/G 三孔

感測器分類總整理
你已經用過三種不同「類型」的元件。現在來整理抽屜——把零散的操作經驗變成有架構的知識
⏱ 約 10 分鐘 · 互動練習
📖
兩把分類尺：訊號類型 × 元件角色
先讀懂這兩個維度，再做練習
▼
🔑
很多人把「訊號類型」和「元件角色」混在一起，才會搞不清楚 DHT11 和光敏電阻有什麼不同。其實這是兩個完全獨立的維度，要分開問：
維度問法可能的答案
訊號類型「它怎麼傳資料給 Arduino？」類比 / 數位 / 通訊協定
元件角色「它是輸入還是輸出？做什麼事？」感測器 / 顯示器 / 執行器

三種訊號類型

〰️
類比訊號：輸出 0～5V 之間的連續電壓，Arduino 用 analogRead(A0) 讀成 0～1023 的整數。
例：光敏電阻、可變電阻、熱敏電阻、土壤溼度感測。
0/1
數位訊號：只有 HIGH（5V）或 LOW（0V）兩個狀態，用 digitalRead() 或 digitalWrite()。
例：按鍵開關、LED、蜂鳴器、繼電器、震動感測。
📦
數位通訊協定：不是簡單高低電位，而是有格式的封包對話，需要引入程式庫才能解碼。常見有四種：
 ・單線自定義（DHT11、DHT22）— 1 條 DATA 線，用 DHT.h
 ・1-Wire（DS18B20 溫度計）— 1 條線可串多個，用 OneWire.h
 ・I²C（SCD41 CO₂、LCD、OLED）— SDA + SCL 兩條線，用 Wire.h
 ・SPI（SD 卡、高速顯示器）— MOSI/MISO/SCK/CS 四條線

✅ 我知道「數位通訊協定」的元件需要額外安裝程式庫

延伸學習：為什麼 OSEP 是「多工」、IDE 是「單工」？
做完九章後，這個問題你一定能懂
▼
💡
現在你已經用過 OSEP Scratch 同時跑 LED 閃爍 + 按鍵偵測 + 感測器讀取，有沒有注意到——這三件事真的同時在動？如果用 Arduino IDE 寫，這其實很難做到。原因就在這裡。

Arduino IDE 燒錄模式 → 單工

程式燒進晶片後，Arduino 脫離電腦獨立執行，只靠自己那顆 16MHz 的小晶片跑一個無限迴圈：

Arduino IDE — loop() 單工執行
void loop() { digitalWrite(13, HIGH); delay(1000); // ← 整個晶片「凍結」1 秒 // 這 1 秒內按鍵沒反應 // 感測器也讀不到 digitalWrite(13, LOW); delay(1000); // ← 又凍結 1 秒 } // 要「同時」做兩件事？ // 必須自己寫 millis() 計時器，難度大幅提升
⏱️
delay() 讓整個 ATmega328P 晶片停下來等待。這段時間內，任何輸入都沒有回應——按鍵、感測器、序列埠全部凍結。這就是「單工」的代價。

OSEP Scratch 連線模式 → 多工

關鍵在於：邏輯不跑在 Arduino 裡，而是跑在你的電腦上。Scratch 本身天生就是多工的——每一堆積木（每個「當綠旗被點擊」或「當訊號收到」）都是一條獨立執行的腳本：

// 這四堆積木在 Scratch 裡同時執行，互不干擾
🏁 綠旗 重複無限次 LED 閃爍
腳本 A
🏁 綠旗 重複無限次 讀按鍵狀態
腳本 B（同時跑）
🏁 綠旗 重複無限次 讀感測器
腳本 C（同時跑）
🏁 綠旗 重複無限次 角色動畫
腳本 D（同時跑）
🧠
Scratch 的多工能力來自電腦的 CPU（現代電腦跑在 GHz 等級，Arduino 才 16MHz）。電腦幫 Arduino「想事情」，Arduino 只負責「動手腳」——輸出電訊號給 LED、讀感測器回傳數字。這就是「多工」的來源。

那什麼時候要用 Arduino IDE？

用 OSEP Scratch 當
✅ 教學示範、課堂練習
✅ 需要同時做多件事
✅ 虛實整合（角色 + 硬體）
✅ 資料記錄到 Google Sheets
✅ 初學者入門
用 Arduino IDE 當
✅ 成品要「單機運作」
✅ 不需連接電腦
✅ 精準計時控制
✅ 進階 C 語言學習
✅ 競賽、作品展部署
一句話總結：
OSEP Scratch = 借用電腦的多工能力，適合教學與快速開發
Arduino IDE = Arduino 自給自足單機執行，適合最終成品部署
→ 這門課用 OSEP 學概念，學完後再升級 IDE 寫 C，這才是完整的學習路徑。
